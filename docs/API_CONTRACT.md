# BLACKOUT API contract — v2 (continuous world, players & auth)

Owner: backend (`apps/api`, `packages/*`). Consumer: `apps/web`. Canonical source of truth is the code in
`packages/shared/src` — this document explains it. If they ever disagree, the code wins and this file is a bug.

```ts
import {
  createApiClient,            // typed fetch client; validates every response with Zod
  GameStatePublicSchema,      // full snapshot the UI renders
  EconomyEventSchema,         // SSE "economy" events the UI animates
  PlayerActionSchema,         // the only way a client can change a run
  fmtCredits, fmtKw, fmtKwh, fmtLitres, fmtKg, fmtRate, fmtClock, // display helpers
} from "@blackout/shared";
```

Every example payload below was generated by `npx tsx scripts/capture-examples.ts` against the real server
and lives in [`docs/examples/`](examples/). Nothing in this file is hand-written JSON.

## 1. Units (all integers)

| Quantity | Field suffix | Unit | Display |
|---|---|---|---|
| credits | `Cc` | centi-credits (100 = ₡1) | `fmtCredits` |
| power | `W` | watts, 100 W quanta | `fmtKw` |
| energy | `Wh` | watt-hours | `fmtKwh` |
| diesel | `Ml` | millilitres | `fmtLitres` |
| CO₂ / permit allowance | `Mg` | milligrams (1 permit = 10 kg = 10,000,000 mg) | `fmtKg` |
| tariff | `CcPerKwh` | centi-credits per kWh | `fmtRate` |
| fuel price | `CcPerL` | centi-credits per litre | |

| heat | `Permille` | 1000 = breakdown | |
| oil index | `Centi` | ×100 (10000 = 100.00) | |

Time: **1 tick = 1 real second = 6 game minutes; 10 ticks = 1 game hour.**
`clock.gameMinuteOfDay` is minutes since 00:00 (the operating day starts 06:00); format with `fmtClock`.

## 2. Timing contract (continuous)

There are no blocking phases. `clock.phase` is always `operating` (or `finished` for Economy Lab runs).
A game day is 240 ticks (24 game hours from 06:00) and is **environmental**: it drives `clock.daylightBps`, solar
output and the evening peak. At each rollover the background economy settles (rent, loyalty, restocks, permit
supply/price, rival shopping, oil step, a `DAY_SETTLED` summary) without interrupting play. `clock.campaignDays` is
`0` for real cities (never ends).

Waves every 30 ticks forever. `clock.wavesTotal ≤ 3` = tutorial (one request, no visible timer, customers wait up to
6 game hours, no heat). `clock.pressureLevel`: 1 = 2 requests with 10 s timers; 2 (from day 2) = heat + rival bids;
3 (day 3 or ≥10 kW capacity) = up to 3 requests. The market, upgrades, servicing and tariffs are always available.

### Clock / pause policy (server-authoritative)
* A city advances only while a client is connected to its SSE stream; 15 s without one → paused
  (`pauseReason: "no_clients"`). Reconnecting resumes. `PAUSE`/`RESUME` actions exist.
* Offline policy: while paused nothing burns, bills or closes. `GET /api/game/state` returns `awayMs`.
* The server never fast-forwards more than 5 s of missed wall time.
* Deadlines are tick numbers: seconds left = `deadlineTick - clock.tick`.

## 3. Endpoints

All responses are `{ ok: true, ... }` or `{ ok: false, error: { code, message, details? } }`.
Auth: guest = `POST /api/session/start` (HTTP-only cookie `bo_session`, also returned as a bearer token);
Google/email = Supabase access token as `Authorization: Bearer <jwt>` (verified against the project JWKS). SSE accepts
`?token=` because `EventSource` cannot set headers. Player ids are always derived from the credential.
The `/api/runs/*` routes remain for tools and tests; the game UI uses `/api/game/*`.

## 4. PlayerAction (discriminated union on `type`)

| type | fields | phase | result |
|---|---|---|---|
| `ACCEPT_REQUEST` | `requestId`, `generatorId?` | operating | `{contractId, status}`; reserves intent only if some source could serve it now |
| `COUNTER_REQUEST` | `requestId`, `rateCcPerKwh` | operating | `{accepted, contractId, customerOfferCcPerKwh, rejected}` (max 2 rounds) |
| `DECLINE_REQUEST` | `requestId` | operating | rival may bid (day ≥ 2) |
| `ASSIGN_CONTRACT` | `contractId`, `generatorId` | operating | capacity reserved; **power starts on the next tick** |
| `CANCEL_CONTRACT` | `contractId` | operating | refunds only unearned escrow |
| `REQUEST_QUOTE` | `sellerId` (`merchant:<id>` \| `regulator`), `item` (`diesel`\|`permit`), `quantity` (mL \| permits) | any | `{quoteId}` (prefer `/quote` route which also returns the quote) |
| `BUY` | `quoteId`, `quantity` | any | `{tradeId, chainStatus}` — the client never sends a price |
| `CREATE_PLAYER_LISTING` | `listingId`, `quantityMl` (100 mL units), `unitPriceCcPerL` | Testnet city, registered player | reserves confirmed, unreserved fuel and queues contract escrow; listable fuel is exposed as `player.listableFuelMl` |
| `CANCEL_PLAYER_LISTING` | `listingId` | Testnet city, registered owner | queues a return from contract escrow; fuel stays reserved until confirmed |
| `SET_TARIFF` | `districtId`, `rateCcPerKwh` (100–3000) | any | affects new requests |
| `SERVICE_GENERATOR` | `generatorId` | any | 60 credits, wear reset, offline first 12 game hours |
| `BUY_UPGRADE` | `upgradeId` (`solar_2kw` \| `battery_10kwh` \| `diesel_5kw`) | any | |
| `UNLOCK_DISTRICT` | `districtId` | any | needs capacity (Hospital Row 10 kW, Tech Hub 15 kW) |
| `READY` | – | — | rejected (`INVALID_PHASE`): nothing to skip in a continuous world |
| `PAUSE` / `RESUME` | – | any | driver control (not recorded in the sim) |

**Idempotency:** generate `idempotencyKey = crypto.randomUUID()` per user intent and **reuse it on retry**. The server
stores the first result (success *or* error) and returns it with `replayed: true`. **Optimistic concurrency:**
`expectedStateVersion` is optional; `stateVersion` bumps on every accepted action and phase change, never on plain ticks.

### Request → contract state machine

```
wave_scheduled ─▶ OUTAGE_STARTED ─▶ CUSTOMER_REQUESTED (request: open)
   request: open ──ACCEPT──▶ accepted ─▶ contract: pending_assignment ──ASSIGN──▶ active ──tick──▶ SERVICE_STARTED
        │   └─COUNTER─▶ customer_countered ─(≤2 rounds)─▶ accepted | rejected_by_customer
        ├─DECLINE─▶ declined ─▶ (day≥2) RIVAL_WON_CONTRACT | RIVAL_DECLINED_CONTRACT
        └─timer─▶ expired ─▶ (day≥2) rival bid
   contract: active ─▶ completed | failed (fuel/permits/breakdown/solar shortfall) | cancelled ; pending_assignment ─timer─▶ expired
   wave.status: outage_started → requests_open → offers_pending → service_active → completed (WAVE_COMPLETED)
```

Lights rule for the UI: a shop is lit iff `business.powerSource !== "none"`. `SERVICE_STARTED` is emitted by the
simulation tick that actually delivered the first energy — **not** by the assign click.

### Trade state machine

```
REQUEST_QUOTE ─▶ quote(open, expiresTick) ─BUY─▶ trade(status: reserved)
  chainStatus "simulation_only" ─▶ settled immediately (guest / chain disabled)
  chainStatus "pending" ─▶ (chain worker signs) "submitted" ─RPC final success─▶ "confirmed" + txHash ─▶ fuel delivered
                                                        └RPC definitive failure─▶ "failed" ─▶ compensated once
                                                        └unknown─▶ reconcile by hash, then by contract.trade_status(); never re-broadcast
```
`txHash` / `explorerUrl` are `null` until an RPC final outcome is verified.

### Player listing / NPC purchase state machine

```
CREATE_PLAYER_LISTING ─▶ reserved (local fuel lock) ─▶ list job submitted ─▶ active (NEP-245 escrow confirmed)
                                                              └definitive failure ─▶ failed + fuel returned
active ──NPC policy accepts──▶ purchase_pending (NPC credits reserved)
  ├─fill confirmed ─▶ filled (resource to NPC account; game credits to player)
  ├─definitive fill failure ─▶ active (NPC credits refunded)
  └─unknown ─▶ stay purchase_pending while hash / contract view reconcile
active ──cancel / seven in-game days──▶ cancel_pending ──confirmed──▶ cancelled / expired (fuel returned)
```

Only registered players in a Testnet-enabled city can list. The NPC rule reads current stockroom space, recent demand,
replacement cost and spendable cash above its operating reserve; the reason map is sent in the game state. Listing
prices and settlement credits remain fictional, off-chain credits. A definitive failed transaction compensates once;
unknown outcomes keep resources and credits reserved until reconciliation. Detailed hashes are only in the optional
Verify panel and `/api/chain/market-listings`.

## 5. Server-Sent Events: `GET /api/runs/:id/events`

```
event: economy   id: <seq>   data: EconomyEvent      (persisted; resume with Last-Event-ID or ?lastEventId=)
event: state                 data: GameStatePublic   (after every tick and every action, ~15 KB)
event: tick                  data: TickFrame         (lightweight; only when no state frame was sent)
: ping                                               (heartbeat every 15 s)
```
Connecting starts a paused run. Missed `economy` events are replayed from the DB first; the server never sends the
same `seq` twice on one connection. Clients should still dedupe by `seq` across reconnects.

### EconomyEvent envelope
`{ seq, eventId, runId, day, tick, clock, type, source, actors[], explanation, data{}, txHash, serverTime }`
`source ∈ simulated_game | testnet_transaction | replay_simulation`. `explanation` is generated from the same numbers
as `data` — show it verbatim in "Why did this happen?".

## 6. Error codes (HTTP status)

`UNAUTHORIZED` 401 · `FORBIDDEN` 403 · `NOT_FOUND` 404 · `VALIDATION_FAILED` 400 · `RATE_LIMITED` 429 ·
`STALE_STATE` `INVALID_PHASE` `INVALID_STATE` `ALREADY_PROCESSED` `RUN_FINISHED` 409 · `CHAIN_UNAVAILABLE` 503 ·
`TX_FAILED` 502 · `ACCOUNT_EXISTS` 409 · `AUTH_PROVIDER_UNAVAILABLE` 503 · `INTERNAL` 500 · all game-rule rejections 422: `REQUEST_EXPIRED`, `MAX_COUNTERS_REACHED`,
`CUSTOMER_CANNOT_PAY`, `CAPACITY_EXCEEDED`, `GENERATOR_OFFLINE`, `INSUFFICIENT_FUEL`, `INSUFFICIENT_PERMITS`, `TANK_FULL`,
`QUOTE_EXPIRED`, `QUOTE_MISMATCH`, `INSUFFICIENT_CREDITS`, `OUT_OF_STOCK`, `RATION_LIMIT`, `MERCHANT_CLOSED`,
`REQUIREMENT_NOT_MET`, `TX_PENDING`. `error.details` carries numbers (e.g. `CAPACITY_EXCEEDED` → `{ratedW, assignedW, requestedW}`)
so the UI can explain "why not" without guessing.

## 7. What the UI must never compute itself
Merchant prices and reasons, customer acceptance, capacity validity, fuel/CO₂/cash, NPC choices, inventory, chain status.
All of these arrive in `GameStatePublic`, `ActionResult.events` or SSE. Request cards already include server-computed
`expectedPaymentCc`, `estimatedFuelMl`, `estimatedCo2Mg`, `estimatedFuelCostCc`, `estimatedMarginCc` and
`customerProfitPerHourCc`.
